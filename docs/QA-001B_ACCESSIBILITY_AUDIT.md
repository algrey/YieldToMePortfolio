# QA-001B — Accessibility and responsive hardening audit

Status: evidence for the QA-001B task (`TASKS.md`). Requirements: PRD-004
(Responsive application shell), QUAL-001 (Accessibility). Normative sections
routed for this task: `PRD-004`/`QUAL-001` in
`docs/REQUIREMENTS_AND_ACCEPTANCE_CRITERIA.md`; "Responsive behavior" and
"Product state contract" in `docs/CONSOLIDATED_PRODUCT_SPEC.md`; responsive,
mobile-relocation, empty/error-state, and interaction/accessibility rules in
`docs/UI_SPEC.md`.

This document records what was verified programmatically (source/markup/CSS
analysis and rendered-output assertions, now encoded in
`tests/qa-001b.test.ts`), the defects found and fixed, defects found and
deliberately deferred, and a named manual checklist for the assistive-tech
and physical-device cases that only an owner running real VoiceOver/hardware
can complete. Nothing in the "manual" section below is claimed as passed —
each row is marked **REQUIRES OWNER RUN**.

## Method

- Read the core-flow components: `app/components/portfolio-shell.tsx` (app
  shell, navigation, Holdings/Overview/Quotes/Details screens, holding
  detail dialogs), `app/components/portfolio-details.tsx`,
  `app/components/import-review.tsx`,
  `app/components/import-history-detail.tsx`,
  `app/components/manual-ledger-entry.tsx`,
  `app/components/account-lifecycle-controls.tsx`/`-recovery.tsx`, and
  `app/globals.css` in full.
- Computed WCAG 2.2 contrast ratios directly from the `:root` colour tokens
  in `app/globals.css` (sRGB relative-luminance formula, no external tool).
- Cross-referenced every interactive control class against its CSS rule for
  `min-height`/`min-width` against the project's 44×44 CSS-pixel policy
  (PRD-004, UI_SPEC §10).
- Verified the reduced-motion media query, the viewport meta configuration
  (`app/layout.tsx`), and the 320 px overflow floor (`html`/`body`
  `min-width`) directly from source.
- Rendered the real (owned-mode) `PortfolioShell` component to static markup
  for the Holdings and Overview screens with fixture data (positive and
  negative gain rows), to verify rendered text — not just source — for the
  colour/sign and chart-table-alternative checks. `PortfolioShell` calls
  `next/navigation`'s `useRouter()`, so the test wraps it in a stub
  `AppRouterContext.Provider`, the same technique Next's own testing guidance
  uses for isolated component rendering.
- Ran `npm run check` (prettier, eslint, `tsc --noEmit`, `vinext check`,
  `vinext build`, and the full `node --test` suite including the new
  `tests/qa-001b.test.ts`) after every fix.

All of this is evidence, not a substitute for the manual checklist in
§4 — automated scans cannot observe screen-reader announcement order, VoiceOver
rotor/landmark behaviour, real pinch-zoom reflow, or physical iPhone safe-area
rendering.

| 1   | Blocking | Positive daily-movement, unrealised-gain, and gain/loss percentage figures in the real (owned) Holdings row grid and holding-detail dialog rendered with **no sign** (e.g. `AUD 12.34`), relying on the `tone-positive` CSS colour class alone to distinguish a gain from a neutral value. Added an Escape-key document listener that closes the drawer while open. Added a manual Tab-containment handler on the drawer element (`onKeyDown`) so Tab/Shift+Tab cycle within the drawer's own focusable elements instead of reaching obscured content behind the overlay.      | `tests/qa-001b.test.ts` "the mobile navigation drawer restores focus, traps Tab, and closes on Escape" (source-verified: the drawer only exists conditionally in the DOM, so behaviour is confirmed via the wiring, matching the existing project pattern in `tests/ui-003.test.ts` "narrow layout and dialog semantics retain overflow and keyboard hooks") |

| 4   | Blocking | Four real interactive controls were below the 44×44 CSS-pixel minimum (PRD-004 acceptance: "Touch targets are at least 44×44 CSS pixels"; CONSOLIDATED_PRODUCT_SPEC "iPhone and narrow screens: Minimum 44×44 CSS-pixel interactive targets", not scoped to icon buttons only): `.period-tabs button` (Details-screen chart period selector, 40×38 px), `.compact-select` (Details-screen "Portfolio value ⌄" selector, 36 px tall, visible at all widths including 320/390/430), `.sheet-close` (the real owned holding-sheet dialog's "Close" button, entirely unstyled, default browser button height), and the Quotes screen's "Close correction history" button (also unstyled).                                                                 | Set `.period-tabs button`/`.compact-select` to 44×44 px minimum; added dedicated `.sheet-close` and `.quote-history-heading`/`.quote-history-heading button` rules with 44×44 px minimums, matching the sizing convention already used by `.dialog-actions button`, `.popover button`/`.popover a`, and `.sheet-heading button` elsewhere in the file.                                                                                          | `tests/qa-001b.test.ts` "interactive controls meet the 44×44 CSS-pixel touch-target minimum" (parses each selector's CSS block and asserts `min-height >= 44px`)                                                                                                                                                                                             |
