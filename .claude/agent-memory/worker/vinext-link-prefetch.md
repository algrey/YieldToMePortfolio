This repo runs on `vinext` (Next-compatible App Router on Vite, per AGENTS.md's approved stack), not real Next.js. Its `<Link>` shim (`node_modules/vinext/dist/shims/link.js`) defaults `prefetch` to `"auto"` mode when the prop is omitted. In `"auto"` mode, `canAutoPrefetchFullAppRoute` (`node_modules/vinext/dist/shims/link-prefetch.js` + the route trie built into `window.__VINEXT_LINK_PREFETCH_ROUTES__`) skips prefetching ONLY when the target route's PATH PATTERN has dynamic segments (e.g. `/portfolio/[id]/holdings`) — `route.isDynamic` here comes from `vinext`'s route-graph builder (`node_modules/vinext/dist/routing/app-route-graph.js`) parsing the URL pattern for `[param]` segments, and has NOTHING to do with whether the page itself is server-rendered dynamically (force-dynamic, per-request auth-gated data, etc.). A fixed-path route like `/` therefore stays eligible for the shared `IntersectionObserver`-driven auto-prefetch even though it is fully dynamic/authenticated at render time.

**Consequence found in this repo (PRF-004, 2026-08-31):** `app/components/portfolio-shell.tsx`'s `topbar-brand` logo `<Link href="/">` is rendered unconditionally in the shared header on every authenticated page and is essentially always in the viewport — so it silently re-triggered a full root-page RSC prefetch fetch on every single tab navigation (observed in production logs as "every navigation ALSO fetches `/`"), roughly doubling server work per click, regardless of whether the owner ever clicked the logo.

**How to apply:** when auditing this repo (or any vinext app) for wasted prefetch traffic, don't assume a dynamic/authenticated PAGE is automatically excluded from auto-prefetch — check whether its URL PATH has bracketed params. Any `<Link>` to a fixed (no-param) route that is unconditionally mounted and normally in-viewport (a logo, a persistent nav item, a header brand mark) is a real prefetch-storm candidate even if the target page is expensive to render. Fix is `prefetch={false}` on that specific link — cheap, local, and only removable this way if the link's own click-time cost (a normal on-demand fetch, same as any other never-prefetched navigation) is an acceptable trade for not paying the background fetch on every unrelated page view. Conditionally-rendered links (inside a closed dropdown/drawer, `{open ? <Link .../> : null}`) are NOT part of this problem class — they never mount until opened, so the shared observer never sees them until the user is already about to plausibly click.
